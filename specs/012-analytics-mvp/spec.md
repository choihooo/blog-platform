**Status**: Draft

## 사용자 시나리오 및 테스트 _(필수)_

### 사용자 스토리 1 - 공개 블로그 이벤트 발행 (Priority: P1)

운영자는 자체 분석 저장소나 대시보드를 만들지 않고도 공개 블로그에서 독자의 주요 행동이 GA4 또는 GTM으로
전송되기를 원한다. 그래야 글 조회, 스크롤 도달, 코드 복사, 목차 이동, 링크 클릭, 검색, 공유 같은 MVP
수준의 독자 행동을 외부 분석 도구에서 확인할 수 있다.

**우선순위 근거**: 이 기능의 핵심 가치는 공개 블로그에서 분석 이벤트를 빠짐없이 발행하는 것이다. 이벤트
발행이 없으면 CMS의 외부 콘솔 링크도 확인할 데이터가 없다.

**독립 테스트**: 분석 provider가 설정된 상태에서 공개 글을 열고 주요 상호작용을 실행한 뒤, 각 행동에
대응하는 이벤트 이름과 글 맥락이 외부 분석 수집기로 전송되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 분석 provider와 공개 글이 설정되어 있을 때, **When** 독자가 글 상세 페이지에 진입하면,
   **Then** `article_view` 이벤트가 글 식별 정보와 함께 한 번 전송된다.
2. **Given** 독자가 글 본문을 읽고 있을 때, **When** 스크롤이 본문 50%와 90% 지점에 처음 도달하면,
   **Then** `scroll_50`과 `scroll_90` 이벤트가 각각 한 번씩만 전송된다.
3. **Given** 글에 코드 블록, 목차, 내부 링크, 외부 링크, 검색 입력, 공유 동작이 있을 때, **When** 독자가
   각 요소와 상호작용하면, **Then** 대응하는 `code_copy`, `toc_click`, `internal_link_click`,
   `external_link_click`, `search`, `share` 이벤트가 전송된다.

---

### 사용자 스토리 2 - 분석 provider 조건부 활성화 (Priority: P2)

운영자는 사이트 설정과 환경에 따라 GA4 또는 GTM을 선택적으로 활성화하고, 분석 설정이 없거나 불완전한
환경에서는 공개 블로그가 오류 없이 동작하기를 원한다. 그래야 로컬 개발, preview, production 환경에서
외부 분석 수집이 의도한 경우에만 활성화된다.

**우선순위 근거**: 분석 이벤트는 production에서만 의미가 크며, 설정 누락이 공개 페이지 실패로 이어지면
MVP 안정성을 해친다. provider 조건부 활성화는 이벤트 발행의 안전장치다.

**독립 테스트**: GA4, GTM, 미설정 상태를 각각 구성해 공개 페이지가 정상 렌더링되고, 설정된 provider에만
이벤트가 전달되는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 사이트 분석 provider가 `ga4`이고 GA measurement id가 있을 때, **When** 공개 페이지가
   렌더링되면, **Then** GA4 수집에 필요한 이벤트 발행 경로가 활성화된다.
2. **Given** 사이트 분석 provider가 `gtm`이고 GTM id가 있을 때, **When** 공개 페이지가 렌더링되면,
   **Then** GTM 수집에 필요한 이벤트 발행 경로가 활성화된다.
3. **Given** provider가 없거나 필요한 공개 id가 누락되어 있을 때, **When** 공개 페이지와 상호작용이
   발생하면, **Then** 페이지는 오류 없이 동작하고 외부 분석 이벤트는 전송되지 않는다.

---

### 사용자 스토리 3 - CMS 외부 분석 콘솔 이동 (Priority: P3)

운영자는 CMS에서 글을 관리하면서 공개 글, GA4 페이지 성과, Search Console 검색 성과 화면으로 빠르게
이동하기를 원한다. 그래야 자체 분석 대시보드를 만들지 않고도 글별 상태 확인과 개선 작업을 이어갈 수
있다.

**우선순위 근거**: 외부 콘솔 링크는 MVP 범위 안에서 분석 확인 경험을 완성하지만, 이벤트 수집 자체보다
우선순위는 낮다. 데이터 저장과 API 기반 대시보드 없이도 운영자의 이동 비용을 줄이는 보조 기능이다.

**독립 테스트**: CMS에서 발행 글을 선택한 뒤 외부 링크를 열어 공개 글 URL, GA4 페이지 성과 URL, Search
Console 성과 URL이 해당 글 맥락을 반영하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** CMS에서 발행 글을 보고 있을 때, **When** 운영자가 공개 글 열기를 선택하면, **Then** 해당
   글의 공개 URL이 새 탐색 대상으로 제공된다.
2. **Given** CMS에서 발행 글을 보고 있고 사이트 URL이 설정되어 있을 때, **When** 운영자가 GA4 페이지
   성과 또는 Search Console 검색 성과 링크를 선택하면, **Then** 해당 글 URL을 확인하기 쉬운 외부 콘솔
   링크가 제공된다.
3. **Given** 글이 초안이거나 공개 slug가 없을 때, **When** CMS가 외부 분석 링크를 표시하면, **Then**
   공개 글 또는 글별 성과 링크는 사용할 수 없는 상태로 구분된다.

### Edge Cases

- 분석 provider가 설정되어 있지만 필요한 공개 id가 없을 때 공개 페이지는 실패하지 않고 분석 전송만
  비활성화해야 한다.
- 같은 글 페이지에서 스크롤 위치가 여러 번 50% 또는 90%를 오가도 각 스크롤 이벤트는 한 번만 전송해야
  한다.
- 외부 링크 클릭은 같은 사이트 내부 링크와 구분되어야 하며, 메일/전화/앵커 링크 같은 특수 URL은 잘못된
  외부 링크 이벤트로 분류되지 않아야 한다.
- 코드 복사 버튼이 여러 개 있을 때 이벤트는 복사된 코드 블록의 글 맥락과 위치를 구분할 수 있어야 한다.
- 검색어가 비어 있거나 공백뿐이면 `search` 이벤트를 전송하지 않아야 한다.
- 브라우저의 기본 공유 기능이 지원되지 않는 환경에서도 공유 버튼은 실패 상태를 사용자에게 과하게 노출하지
  않고 fallback 동작을 제공해야 한다.
- CMS 외부 콘솔 링크에 필요한 사이트 URL 또는 글 slug가 없으면 잘못된 URL을 제공하지 않아야 한다.

## 요구사항 _(필수)_

### 기능 요구사항

- **FR-001**: 시스템은 `article_view`, `scroll_50`, `scroll_90`, `code_copy`, `toc_click`,
  `internal_link_click`, `external_link_click`, `search`, `share` 이벤트를 블로그 이벤트 목록으로
  정의해야 한다.
- **FR-002**: 시스템은 각 블로그 이벤트에 이벤트 이름, 공개 글 식별 정보, 공개 URL, 발생 위치 또는 대상,
  발생 시각을 포함한 일관된 payload를 제공해야 한다.
- **FR-003**: 시스템은 분석 provider가 `ga4`이고 필요한 공개 id가 설정된 경우에만 GA4 수집 경로를
  활성화해야 한다.
- **FR-004**: 시스템은 분석 provider가 `gtm`이고 필요한 공개 id가 설정된 경우에만 GTM 수집 경로를
  활성화해야 한다.
- **FR-005**: 시스템은 분석 provider가 없거나 필요한 공개 id가 누락된 경우 외부 분석 전송을 수행하지
  않되, 공개 페이지와 독자 상호작용은 정상 동작하게 해야 한다.
- **FR-006**: 시스템은 공개 글 상세 진입 시 `article_view` 이벤트를 글 페이지 표시당 한 번 전송해야
  한다.
- **FR-007**: 시스템은 독자가 글 본문 50%와 90% 지점에 처음 도달했을 때 `scroll_50`과 `scroll_90`
  이벤트를 각각 한 번만 전송해야 한다.
- **FR-008**: 시스템은 코드 블록 복사 성공 시 `code_copy` 이벤트를 전송해야 한다.
- **FR-009**: 시스템은 목차 항목 클릭 시 `toc_click` 이벤트를 클릭한 heading 정보와 함께 전송해야 한다.
- **FR-010**: 시스템은 공개 블로그 내부 URL 클릭과 외부 URL 클릭을 구분해 각각
  `internal_link_click`, `external_link_click` 이벤트를 전송해야 한다.
- **FR-011**: 시스템은 유효한 검색어가 제출될 때 `search` 이벤트를 전송해야 한다.
- **FR-012**: 시스템은 독자가 글 공유 동작을 완료하거나 fallback 공유 동작을 실행할 때 `share` 이벤트를
  전송해야 한다.
- **FR-013**: CMS는 발행 글에 대해 공개 글 열기 링크를 제공해야 한다.
- **FR-014**: CMS는 발행 글에 대해 GA4 페이지 성과 확인 링크와 Search Console 검색 성과 확인 링크를
  제공해야 한다.
- **FR-015**: CMS는 초안, 보관 글, 공개 slug가 없는 글에 대해 글별 외부 분석 링크를 사용할 수 없는
  상태로 표시해야 한다.
- **FR-016**: 이 feature는 자체 분석 데이터 저장소, 자체 분석 대시보드, GA4 Data API 조회, Search
  Console API 조회, 서버 측 이벤트 수집 기능을 포함하지 않아야 한다.
- **FR-017**: 분석 이벤트 발행은 공개 블로그의 콘텐츠 노출 정책을 변경하지 않아야 하며, 초안과 보관 글을
  공개 분석 대상으로 만들지 않아야 한다.

### 핵심 엔티티

- **Blog Event**: 공개 블로그에서 발생하는 독자 행동. 이벤트 이름, 글 맥락, 대상, 발생 시각을 포함한다.
- **Analytics Provider Setting**: 사이트가 사용할 외부 분석 provider와 활성화에 필요한 공개 식별자 상태.
- **Article Analytics Context**: 이벤트와 외부 콘솔 링크에 공통으로 쓰이는 공개 글의 slug, title,
  canonical URL, category, tag, author 같은 맥락 정보.
- **Scroll Milestone State**: 한 페이지 표시 동안 50%와 90% 스크롤 이벤트가 이미 전송되었는지 나타내는
  일시적 상태.
- **External Console Link**: CMS에서 외부 분석 콘솔 또는 공개 글로 이동하기 위한 글별 링크 표현.

## 성공 기준 _(필수)_

### 측정 가능한 결과

- **SC-001**: 분석 provider가 올바르게 설정된 공개 글 상세 진입의 100%에서 `article_view` 이벤트가 한
  번 전송된다.
- **SC-002**: 동일한 글 페이지 표시에서 `scroll_50`과 `scroll_90` 이벤트가 각각 최대 한 번만 전송되는
  비율이 100%다.
- **SC-003**: 코드 복사, 목차 클릭, 내부 링크 클릭, 외부 링크 클릭, 검색, 공유 상호작용의 95% 이상이
  대응하는 이벤트 이름과 글 맥락을 포함해 전송된다.
- **SC-004**: 분석 provider 또는 필요한 공개 id가 누락된 환경에서 공개 페이지 렌더링 실패와 사용자
  상호작용 오류가 0건이어야 한다.
- **SC-005**: CMS의 발행 글 100%에서 공개 글 열기, GA4 페이지 성과, Search Console 검색 성과 링크가
  제공되거나, 필요한 설정이 없을 때 명확히 비활성화된다.
- **SC-006**: 초안, 보관 글, 공개 slug가 없는 글에서 글별 외부 분석 링크가 잘못된 공개 URL로 제공되는
  사례가 0건이어야 한다.
- **SC-007**: 이 feature 완료 후에도 자체 분석 저장소, 자체 대시보드, GA4/Search Console API 조회
  기능이 MVP 범위에 추가되지 않는다.

## 가정

- 이 feature는 기존 콘텐츠 모델, 공개 블로그 렌더링, 발행 workflow, generated outputs가 존재한다는
  전제에서 진행한다.
- `content/site.json`의 분석 provider 설정이 GA4 또는 GTM 사용 여부를 결정하며, 필요한 공개 id는 배포
  환경별 설정에서 제공된다.
- GA4와 GTM은 동시에 활성화하지 않고 사이트 설정의 단일 provider를 따른다.
- 이벤트는 공개 독자 행동 분석을 위한 최소한의 글 맥락만 포함하며, 개인 식별 정보나 CMS 관리자 전용
  정보를 포함하지 않는다.
- CMS 외부 콘솔 링크는 외부 서비스의 URL 형식 변경 가능성을 감안해 가장 안정적인 글 URL 기반 이동을
  우선한다.
- Post-MVP의 Analytics API Dashboard는 이 명세 범위 밖이며, 추후 별도 명세에서 다룬다.
