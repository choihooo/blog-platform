# Feature Specification: GA/GSC 성과 대시보드

**Feature Branch**: `[015-ga-gsc-dashboard]`

**Created**: 2026-07-31

**Status**: Draft

**Input**: User description: "GA4와 Google Search Console 실제 수치를 CMS 안에서 보여주는 분석
대시보드. 최근 7/28일 page views, active users, top posts, search clicks/impressions/CTR/position,
글별 GA/GSC 비교, publish 이후 성과 추적을 포함한다."

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 사이트 성과 요약 확인 (Priority: P1)

블로그 운영자는 CMS에서 최근 사이트 성과를 한 화면으로 확인해 발행 효과와 검색 유입 상태를 빠르게
판단한다.

**Why this priority**: 운영자가 외부 콘솔을 오가며 수치를 찾지 않아도 글 운영 판단을 할 수 있어야 이
기능의 핵심 가치가 생긴다.

**Independent Test**: 연결된 분석 계정이 있는 상태에서 대시보드에 진입하면 최근 7일과 28일 기준의
주요 방문 및 검색 성과가 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 분석 계정 연결이 완료되어 있고 최근 방문 데이터가 있는 상태, **When** 운영자가 CMS 분석
   대시보드를 연다, **Then** 최근 7일과 28일의 방문 수, 활성 사용자 수, 검색 클릭 수, 노출 수, 평균
   CTR, 평균 게재 순위가 표시된다.
2. **Given** 이전 기간과 비교 가능한 데이터가 있는 상태, **When** 운영자가 요약 지표를 본다,
   **Then** 각 지표는 직전 동일 기간 대비 증가, 감소, 변화 없음 중 하나로 표시된다.
3. **Given** 분석 계정은 연결되어 있으나 최근 데이터가 없는 상태, **When** 운영자가 대시보드를 연다,
   **Then** 빈 상태 메시지와 다음 확인 시점이 표시된다.

---

### User Story 2 - 글별 성과 비교 (Priority: P2)

블로그 운영자는 개별 글 단위로 방문 성과와 검색 성과를 함께 비교해 어떤 글이 읽히고 어떤 검색어로
발견되는지 판단한다.

**Why this priority**: 글 중심 블로그에서는 사이트 전체 합계보다 글별 성과가 콘텐츠 개선과 후속 발행
주제를 결정하는 데 더 직접적이다.

**Independent Test**: 발행 글 목록이 있는 상태에서 글별 분석 표를 열고 특정 글을 선택했을 때 해당
글의 방문 지표와 검색 지표가 함께 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행된 글과 분석 데이터가 있는 상태, **When** 운영자가 글별 성과 목록을 본다, **Then**
   각 글은 제목, slug, 발행일, 최근 방문 수, 활성 사용자 수, 검색 클릭 수, 노출 수, CTR, 평균 게재
   순위를 함께 표시한다.
2. **Given** 운영자가 글별 성과 목록을 정렬할 수 있는 상태, **When** 방문 수, 검색 클릭 수, 노출 수,
   CTR 중 하나로 정렬한다, **Then** 목록은 선택한 지표 기준으로 정렬된다.
3. **Given** 특정 글에 검색 성과는 있으나 방문 성과가 없는 상태, **When** 운영자가 해당 글을 본다,
   **Then** 누락된 지표는 0 또는 데이터 없음으로 구분되어 표시된다.

---

### User Story 3 - 발행 이후 성과 추적 (Priority: P3)

블로그 운영자는 새 글 발행 후 일정 기간 동안 성과 변화를 추적해 제목, 요약, 내부 링크, 후속 글 주제
개선 여부를 판단한다.

**Why this priority**: 발행 직후 성과 추적은 개별 글 운영 개선에 유용하지만, 전체 요약과 글별 비교가
먼저 동작해야 의미가 있다.

**Independent Test**: 최근 발행 글이 있는 상태에서 발행 후 1일, 7일, 28일 단위의 성과 변화가
표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 최근 28일 안에 발행된 글이 있는 상태, **When** 운영자가 발행 이후 성과 섹션을 본다,
   **Then** 글별로 발행 후 1일, 7일, 28일 누적 성과가 표시된다.
2. **Given** 발행 후 충분한 시간이 지나지 않은 글이 있는 상태, **When** 운영자가 해당 글의 추적
   정보를 본다, **Then** 아직 도달하지 않은 기간은 대기 상태로 표시된다.
3. **Given** 발행 글의 성과가 기준치보다 낮은 상태, **When** 운영자가 발행 이후 성과를 본다,
   **Then** 개선 검토가 필요한 글로 구분되어 표시된다.

---

### Edge Cases

- 분석 계정 연결이 끊겼거나 권한이 부족하면 운영자가 재연결 또는 권한 확인이 필요하다는 상태를 볼 수
  있어야 한다.
- 일부 글의 URL이 변경되었거나 canonical 경로가 불일치하면 해당 글은 매칭 불완전 상태로 표시되어야
  한다.
- 검색 데이터는 충분한 표본이 없을 때 평균 순위나 CTR이 왜곡될 수 있으므로 낮은 표본 상태가
  구분되어야 한다.
- 분석 데이터 제공 지연으로 오늘 또는 최근 날짜 수치가 비어 있으면 마지막으로 확인 가능한 날짜가
  표시되어야 한다.
- 보관 글과 초안은 기본 목록에서 제외하되, 과거 성과 확인이 필요한 경우 별도 필터로 확인 가능해야
  한다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: CMS는 인증된 운영자에게만 GA/GSC 성과 대시보드 접근을 허용해야 한다.
- **FR-002**: 시스템은 분석 계정 연결 상태, 마지막 데이터 동기화 시각, 데이터 제공 가능 날짜 범위를
  표시해야 한다.
- **FR-003**: 운영자는 최근 7일과 28일 기준으로 사이트 전체 방문 수, 활성 사용자 수, 검색 클릭 수,
  검색 노출 수, 평균 CTR, 평균 게재 순위를 확인할 수 있어야 한다.
- **FR-004**: 시스템은 각 요약 지표에 대해 직전 동일 기간 대비 변화 방향과 변화량을 표시해야 한다.
- **FR-005**: 운영자는 발행 글별 방문 성과와 검색 성과를 하나의 목록에서 비교할 수 있어야 한다.
- **FR-006**: 글별 목록은 제목, slug, 발행일, 상태, 방문 수, 활성 사용자 수, 검색 클릭 수, 검색 노출
  수, CTR, 평균 게재 순위를 포함해야 한다.
- **FR-007**: 운영자는 글별 목록을 기간, 상태, 카테고리, 태그, 성과 지표 기준으로 필터링하고 정렬할
  수 있어야 한다.
- **FR-008**: 운영자는 특정 글을 선택해 해당 글의 기간별 성과 추이와 대표 검색어를 확인할 수 있어야
  한다.
- **FR-009**: 시스템은 최근 발행 글에 대해 발행 후 1일, 7일, 28일 누적 성과를 표시해야 한다.
- **FR-010**: 시스템은 분석 데이터와 글 slug 또는 canonical URL을 매칭하고, 매칭되지 않는 항목을
  운영자가 확인할 수 있도록 표시해야 한다.
- **FR-011**: 데이터가 없거나 계정 권한이 부족하거나 외부 분석 서비스가 일시적으로 응답하지 않는
  경우, 시스템은 마지막 성공 데이터 또는 명확한 빈 상태를 표시해야 한다.
- **FR-012**: 운영자는 필요할 때 외부 GA4 및 Google Search Console 원본 화면으로 이동할 수 있어야
  한다.
- **FR-013**: 시스템은 초안의 분석 데이터를 기본적으로 표시하지 않아야 하며, 공개된 이력이 있는 보관
  글은 운영자 필터 선택 시에만 표시해야 한다.
- **FR-014**: 시스템은 개인 식별 가능한 방문자 정보를 표시하지 않고 집계 지표만 표시해야 한다.

### Key Entities _(include if feature involves data)_

- **Analytics Connection**: 운영자의 분석 데이터 연결 상태를 나타낸다. 연결 계정, 권한 상태, 마지막
  확인 시각, 오류 상태를 포함한다.
- **Site Performance Summary**: 선택 기간의 사이트 전체 성과를 나타낸다. 방문, 활성 사용자, 검색
  클릭, 노출, CTR, 평균 게재 순위, 이전 기간 대비 변화 정보를 포함한다.
- **Post Performance**: 발행 글 하나의 분석 성과를 나타낸다. 글 식별 정보, 발행 정보, 방문 성과,
  검색 성과, 매칭 상태를 포함한다.
- **Search Query Performance**: 특정 글 또는 사이트 전체에 연결된 검색어 성과를 나타낸다. 검색어,
  클릭, 노출, CTR, 평균 게재 순위를 포함한다.
- **Publication Performance Window**: 발행 후 1일, 7일, 28일 같은 고정 기간의 누적 성과를 나타낸다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 운영자는 CMS 진입 후 30초 안에 최근 7일과 28일의 핵심 사이트 성과를 확인할 수 있다.
- **SC-002**: 운영자는 2분 안에 최근 28일 기준 상위 성과 글 10개와 하위 개선 후보 글 10개를 식별할
  수 있다.
- **SC-003**: 발행 글 중 95% 이상이 분석 데이터와 올바른 slug 또는 canonical URL로 매칭된다.
- **SC-004**: 데이터 연결 오류가 발생해도 운영자는 10초 안에 원인 상태와 다음 조치 또는 마지막 성공
  데이터 여부를 확인할 수 있다.
- **SC-005**: 운영자는 새 글 발행 후 28일 이내에 발행 후 1일, 7일, 28일 성과를 한 화면에서 비교할 수
  있다.
- **SC-006**: 대시보드 사용자 테스트에서 운영자의 90% 이상이 외부 콘솔을 열지 않고도 "성과가 좋은
  글", "검색 개선이 필요한 글", "최근 발행 글의 초기 성과"를 식별한다.

## Assumptions

- 이 기능은 MVP 이후 확장 기능이며, 기존 MVP의 외부 콘솔 링크 제공 원칙을 대체하지 않고 CMS 내부
  요약과 비교 경험을 추가한다.
- 대상 사용자는 단일 블로그 운영자이며, 공개 독자는 이 대시보드에 접근하지 않는다.
- GA4와 Google Search Console 속성은 이미 블로그 도메인과 연결되어 있거나 연결 가능하다.
- 지표는 방문자 개인을 식별하지 않는 집계 데이터만 다룬다.
- 기본 기간은 최근 7일과 28일이며, 더 긴 기간 비교는 후속 확장으로 다룬다.
- "개선 검토가 필요한 글"의 기본 기준은 같은 기간 발행 글 중앙값보다 방문 또는 검색 클릭이 50% 이상
  낮은 경우로 간주한다.
- 분석 데이터 제공 지연은 정상 상황으로 취급하며, 대시보드는 마지막으로 확인 가능한 날짜를 기준으로
  표시한다.
