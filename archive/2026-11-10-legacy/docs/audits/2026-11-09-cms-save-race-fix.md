# CMS 저장 응답 경쟁 수정 — 2026-11-09

## 문제와 수정

저장 요청 이후 입력한 내용이 제출 당시 문서를 적용하는 성공·실패 응답으로 덮였다. `useTransition`
안에서 Promise를 분리해 실제 응답 대기 중에도 다음 저장이 시작될 수 있었다.

- 편집 revision과 동기 document ref를 기준으로 응답을 반영한다. 새 편집이 있으면 본문과 변경한
  frontmatter를 유지하며, 저장 경로·SHA·저장 시각과 변경하지 않은 서버 확정 필드만 반영한다.
- 새 편집은 dirty 상태로 남는다. 로컬 백업을 새 저장 경로와 SHA로 갱신하고 이전 draft 키를 정리한다.
  추가 편집이 없을 때만 해당 저장의 백업을 삭제한다.
- 저장·발행·공개 해제·보관·미리보기·공개 갱신 재시도에 단일 in-flight guard를 적용한다. 요청 거부
  시에도 입력을 보존하고 guard를 해제한다.
- 발행 저장 성공/공개 갱신 실패 시 저장 버전과 새 입력을 함께 유지하며, 재시도는 공개 갱신만
  실행한다.
