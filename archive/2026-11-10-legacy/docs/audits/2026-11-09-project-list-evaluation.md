# 대표 프로젝트 목록 응답 평가

사용자 요청에 따라 `대표 프로젝트`(p1)를 특정 상세 URL 검색이 아닌 프로젝트 목록 응답으로 평가하도록
변경했다. 실제 검색·챗봇·프로젝트 페이지 구현은 바꾸지 않았다.

## 새 기준

- `responseType: project-list`, group `project-list`로 공개 `/api/rag`에서 검사한다.
- 서로 다른 공개 프로젝트 2개 이상이 있어야 한다. 링크는 fixture의 공개 프로젝트 allowlist에
  포함되고 제목과 설명이 비어 있지 않아야 하며, 답변에도 각 제목이 포함돼야 한다.
- `ai-workflow` 같은 특정 프로젝트는 필수가 아니다. 동일 프로젝트 링크를 반복하거나, 등록되지 않은
  링크·제목 누락·설명 누락·오류 응답은 통과하지 않는다.
- Worker `/search`·`/answer` 직접 평가에서는 목록 항목을 건너뛴다. 목록 결과는
  `summary.projectLists`의 total/passed로 따로 집계하고 검색 Recall 분모에 섞지 않는다.
- 소개 내용의 의미적 정확성은 별도 검토한다. 구조 검사가 사람의 내용 검수를 대신하지 않는다.

## 검증

통과·실패 경계와 CLI 필터를 테스트로 먼저 재현한 뒤 구현했다. 실제 `projectCatalog`에서
`ai-workflow`를 제외한 목록도 새 기준으로 통과한다. 후속 질문의 p1 context 참조는 유지한다.

2026-11-09에 저장한 실제 공개 API의 대표 프로젝트 응답을 새 평가 함수에 적용한 결과:

- 프로젝트 목록: 1/1 통과. 제목·설명·링크 3개가 있으며 답변에 해당 제목들이 포함된다.
- 이력서 제외 후 남은 raw 검색: positive 17개 중 16개 적중(94.1%), 부정 오탐 0/10.
- 남은 raw 검색 실패는 p5 `거부기린 사용자 성과`다.

이 수치는 저장한 응답의 **사후 재집계**이며 새로운 API 실험이나 검색 품질 개선을 뜻하지 않는다. 기존
85%/88.9% 보고서는 당시 범위의 원본으로 보존한다. 현재 fixture는 전체 44개로 동일하지만, 긍정 검색
17·부정 10·calibration 8·목록 1·후속 5·주입 3으로 분류된다.

`pnpm --filter @blog-platform/blog test` 462개, lint·typecheck·build를 통과했다. 평가
자료·스크립트만 변경해 SEO 검사는 생략한다. API·데이터 쓰기·운영 배포는 하지 않았다. 전체 운영
승인과 사람 검수는 이 평가 범위 변경으로 대신하지 않는다.
