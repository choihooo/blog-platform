# RAG 태그·카테고리 반영

## 구현 (2026-09-06)

- 공개 게시글 조회 시 `posts.category_id`로 카테고리와 부모 카테고리를 읽는다.
- `post_tags`와 `tags`에서 태그 이름·슬러그를 읽는다. 상관 서브쿼리로 게시글 중복을 방지한다.
- 각 500자 청크의 임베딩 입력에 제목, 카테고리 이름·슬러그, 태그 이름·슬러그, 본문을 넣는다. 긴 글의
  마지막 청크도 동일한 분류를 포함한다.
- 태그 순서를 정규화하고 중복을 제거한다. 분류 변경은 청크 ID를 변경하므로 다음 동기화에서 새 벡터를
  생성한다.
- 응답용 본문에는 분류 문자열을 섞지 않아 기존 글 요약 UI를 유지한다.
- 글/블로그를 명시한 검색에서는 이력서·프로젝트 결과를 제외한다.
- 기존 벡터는 삭제하지 않는다. 검색 후보를 100개까지 받아 현재 공개 데이터의 ID와 일치하는 결과만
  사용한다. 오래된 벡터가 계속 쌓이면 별도 정리/세대별 인덱스 전환이 필요하다.

## 범위와 동기화

태그·카테고리는 **의미 검색용 임베딩 입력**이다. Vectorize의 별도 메타데이터 인덱스나 강제 필터는
추가하지 않았다. 따라서 카테고리별 전체 글 목록을 정확히 나열하는 DB 필터 API와는 다르다.

기존 게시글 재검증 API가 개별 글을 동기화한다. 카테고리 자체를 일괄 개명하거나 D1을 직접 변경한
경우에는 전체 동기화를 실행해야 한다. 데이터 변경 자체를 감시하는 트리거는 없다.

```sh
pnpm --filter @blog-platform/rag-worker sync
```

기존 로컬 Worker와 `.dev.vars`의 관리자 인증을 사용한다. 게시글·태그·카테고리 원본은 수정하지
않는다. 운영 코드 배포는 별도 작업이다.

## 검증

- 모든 청크의 분류 포함, 순서 변경에 대한 ID 안정성, 태그·카테고리 변경 시 ID 무효화 테스트.
- Worker 실제 임베딩 호출 인자 및 공개 게시글/부모 카테고리 조회 테스트.
- 원격 인덱스 동기화 완료: 총 525청크 중 게시글 440청크 새 임베딩 생성, 기존 정적 자료 85청크
  재사용.
- 로컬 API에서 `AI 태그 글 있어?`는 AI 이슈 트래커, AI 디자인 시스템, AI 에이전트 비교 글을
  반환했다.
