# 포트폴리오 챗봇 검색·대화 개선 — 2026-09-06

## 적용 범위

- `대표 프로젝트`, `프로젝트 목록`, `개인/사이드 프로젝트`는 `/projects`와 동일한 실제 데이터에서
  최대 3개씩 소개한다. 원문 제목·설명·링크를 사용하며 생성 모델로 수치를 재작성하지 않는다.
- 제목·태그·카테고리 키워드를 현재 공개 코퍼스에서 검색한다. 의미 없는 요청 표현과 영문 기술명 뒤
  한국어 조사를 정리하고, 영문 단어 경계로 `AI`가 `chair`에 매칭되는 것을 막는다.
- 유효 검색어의 절반 이상이 메타데이터에 있으면 해당 문서들을 우선 사용한다. 이 후보가 없을 때 기존
  벡터 유사도 0.48 기준을 사용한다. 단순히 임계값을 낮추지는 않았다. 메타데이터 점수는 정렬용 값이며
  확률/코사인 유사도가 아니다.
- 삭제·비공개·변경 전 벡터 ID는 계속 제외한다. 메타데이터 검색도 현재 공개 원문에서만 수행한다.
  비공개 정보나 오래된 벡터 metadata를 답변 근거로 쓰지 않는다.
- 직전 검색 질문과 실제 표시한 출처 제목만 다음 질문에 전달한다. 모델이 생성한 문장은 다음
  검색·답변의 근거로 전달하지 않는다. `첫 번째`, `2번`, `그거`, `관련 글` 같은 후속 표현을 처리하며
  후보가 여러 개면 명확히 되묻는다. 별개의 질문에는 이전 주제를 붙이지 않는다.
- `clarification`과 `no-evidence` 상태를 분리했다. 검색이 약하다고 글이 존재하지 않는다고 단정하지
  않는다. 429/503은 기존의 요청 제한/검색 장애 안내로 구별한다. 실패한 별개의 질문 뒤에는 이전
  주제가 잘못 이어지지 않도록 문맥을 비운다.
- 방문자 채팅의 개발 진단 영역은 기본 비노출이다. 기존 진단 도구는 `PortfolioChat diagnostics`를
  명시한 개발용 렌더링에서만 사용할 수 있다. 별도의 공개 진단 URL은 만들지 않았다.

## 임베딩 점검

기존 로컬 Worker와 Cloudflare 연결로 sync를 끝까지 실행했다. 현재 유효 조각 525개 모두 기존
Vectorize ID가 있었으며 전체 배치 `indexed: 0`, 마지막 `nextOffset: null`을 확인했다. 이번 확인
시점에 누락된 임베딩은 발견되지 않았다. D1 원문·스키마·요금제·도메인을 바꾸거나 운영 Worker를
배포하지 않았다.

## 검증

- `node apps/blog/scripts/check-rag.mjs`: 실제 localhost:3001 API 30문항 검사. 초기 구현 및
  메타데이터 우선순위 보완 후 두 번 모두 **30/30 통과**. 소개·경력·성과·프로젝트
  목록·React/AI/메모이제이션 글·순서 지칭·모호한 지칭·검색 근거 없음 포함.
- 검사 기준은 API 정상 상태, 실제 출처 경로/제목, 고정 사실 답변 존재 및 질문 재작성이다. **30문항
  전체의 브라우저 생성 문장을 평가한 것은 아니다.**
- 브라우저: 추천 버튼 클릭으로 3개 프로젝트 노출, `2번 성과`가 Nexacro의 5/5 및 100% 명세 추출
  성과로 연결됨을 확인했다. `React 글 추천`에서 리액트 개발 도구·throttle/debounce의 실제 제목
  링크와 요약이 스트리밍되는 것을 확인했다. 최종 완료 시점 전에 사용자가 이력서로 이동하여 완료 상태
  재확인은 하지 않았다. 개발 진단 영역 비노출 확인.
- 기존 회귀 검사 중 CSS 파일이 반드시 선택자로 시작해야 한다는 검사는 최상위 keyframes를 허용하도록
  수정했다. 삭제 벡터 검사도 현재 메타데이터 검색과 충돌하지 않는 비공개 글 질문으로 유지했다.
- 최종 Blog **25파일 134테스트**, lint·production build 통과. Worker **5테스트**, typecheck 통과. 팀
  프로젝트 목록은 회사 소속이 아니라 실제 `team` 필드로 구분하는 회귀 검사도 포함했다.

## 남은 한계

- 후속 질문 처리는 짧은 한국어 표현 및 직전 문맥 한 단계에 한정된다. 모든 대명사·장기 대화를
  이해하는 의미 분류기는 아니다.
- 메타데이터 검색은 키워드 기반이며 동의어 전체를 포괄하지 않는다. 폭넓은 기술 선택·협업 질문이나
  작은 모델의 일반 생성 답변에는 추가 평가가 필요하다.
- 브라우저에 제공하는 발췌는 기존 최대 2개/600자 제한을 유지한다. 긴 프로젝트 전체 분석·서로 다른
  프로젝트 비교를 완전히 지원한다고 보장하지 않는다.
- 모든 공개 데이터가 없을 때 자동으로 답을 만드는 것이 아니라 근거 범위를 안내한다. 운영 배포 전
  실제 질문 로그를 비식별화해 테스트 사례를 확장하는 것이 다음 검증 단계다.
