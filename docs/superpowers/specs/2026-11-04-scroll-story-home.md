# 스크롤 스토리 메인 전환 사양

## 목적과 범위

`/experiments/scroll-story`에서 검토한 3개 장면을 `/`의 정식 홈으로 사용한다.
기존 픽셀룸은 메인에서 내리고 `/experiments/pixel-room`에 검색에 노출하지 않는 보관 페이지로 유지한다.
이번 문서는 계획이며 구현·배포는 아직 하지 않는다.

## 화면과 주소

| 순서 | 장면 | 제목 / 설명 | 바로가기 |
| --- | --- | --- | --- |
| 1 | 인사 / About | 안녕하세요 호조리카입니다 / 잘부탁드립니다 | About 바로가기 → `/resume` |
| 2 | 글쓰기 / Blog | 블로그 / 배운 것들을 기록합니다. | 블로그 바로가기 → `/blog` |
| 3 | 작업 / Portfolio | 포트폴리오 / 직접 만든 작업들입니다. | 포트폴리오 바로가기 → `/projects` |

- 현재 승인된 캐릭터·배경색·제목 상단 배치·기존 폰트 상속·44×44px 이상 버튼을 유지한다.
- 새 영상 생성은 하지 않는다. `public/brand/scroll-story/plates-centered`의 가로·세로 반복/전환 MP4와 JPG를 사용한다.
- 반복 영상은 현재 장면만 재생한다. 장면 선택마다 기존 방향별 전환 영상을 한 번 재생한다.
- 제목·소개·바로가기는 HTML로 유지한다. 헤더 장면 메뉴와 다음 버튼으로도 이동한다.
- 일반 `/` 진입은 인사 장면이다. `/#about`, `/#blog`, `/#work`는 해당 장면으로 진입한다.
- 장면 확정 시 hash는 `replaceState`로 갱신해 장면마다 뒤로 가기 기록을 추가하지 않는다.
- 상세 방문 후 브라우저 뒤로 가기로 돌아오면 기존 hash의 장면을 정지 상태로 복원한다.
- 실험 주소 `/experiments/scroll-story`는 `/`로 영구 리디렉션한다.
- 블로그·프로젝트·이력서·글·카테고리·검색의 기존 URL 및 일반 페이지 탐색을 유지한다.

## 운영 품질

- 영상 로드 실패, 재생 거절, 전환 4초 초과 시 JPG와 목적 장면의 링크를 표시한다. 화면을 잠근 채 기다리지 않는다.
- reduced motion은 최초 페인트부터 JPG를 표시하고 영상 재생·문구 애니메이션·부드러운 스크롤을 사용하지 않는다.
- 빠른 About → Blog → About 선택 뒤 늦게 끝난 이전 영상 이벤트가 새 장면을 덮어쓰지 않아야 한다.
- 숨겨진 장면의 링크에는 키보드 포커스가 가지 않는다. 현재 메뉴와 표시된 장면이 일치한다.
- 모바일 주소창·화면 회전·가로 전환에도 현재 장면을 유지하며 제목·CTA·챗봇이 겹치지 않는다.
- JavaScript 미실행 시 인사 제목 및 About·Blog·Portfolio 일반 링크로 이동할 수 있다.
- 챗봇은 스크롤 컨테이너 밖에서 현재 UI/검색/모델을 재사용한다. 홈 진입만으로 GGUF 모델을 다운로드하지 않고 최초 채팅 열기 때 시작한다.
- 홈페이지 canonical `/`, 기존 Person JSON-LD, 운영 OG·Twitter·분석 태그를 보존한다. 실험 페이지의 noindex를 복사하지 않는다.
- 픽셀룸 보관 페이지는 noindex이며 홈 메뉴에 추가하지 않는다. 정식 홈에서 `/pixel/*` 이미지 요청이 없어야 한다.

## 현재 코드에서 확인한 사실

- 홈은 `app/page.tsx`의 `<PixelRoom />`이며 Person JSON-LD를 함께 출력한다.
- 실험 페이지가 `ScrollStory`와 `PortfolioChat`을 조합한다. 챗봇 스타일은 `pixel-room.css`를 재사용한다.
- `HomeAwareShell`은 `/`와 스크롤 실험 주소에서 공용 헤더를 숨긴다.
- 실제 `app/@modal` 또는 가로채기 라우트는 없다. 기존 상세는 이미 일반 페이지다.
- 현재 챗봇은 지원 브라우저에서 mount 직후 모델을 자동 로드한다.
- 기존 Vitest는 Node 환경이다. 브라우저 동작은 실제 브라우저 QA로 검증하고 테스트 프레임워크를 추가하지 않는다.

## 제외·보존

- 픽셀룸 원본·에셋 영구 삭제, 챗봇 전체 폴더 이동, 콘텐츠 DB 변경, 썸네일 재변경은 제외한다.
- 썸네일·OG 작업과 홈 시안의 미커밋 변경을 보존하고 변경 소유 범위를 구분한다.
- 정식 전환이 안정된 뒤 픽셀룸 삭제 여부는 별도 작업으로 결정한다.
