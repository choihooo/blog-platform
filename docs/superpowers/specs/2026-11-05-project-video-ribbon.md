# Hozorica 프로젝트 Video Ribbon 설계안

상태: 검토용 제안. 사용자는 레퍼런스 기반 계획 작성을 요청했으며 구현·배포는 아직 시작하지 않았다.

## 목적과 범위

개발자 최호의 작업을 시각적으로 소개하고 실제 프로젝트 상세로 연결한다. `/projects` 목록을
스크롤에 따라 영상·이미지 카드가 공간을 지나가는 쇼케이스로 변경한다. 독립 실험 경로에서 먼저
확인한 후 목록에 적용한다. `/`의 캐릭터 3개 장면, `/blog`, `/resume`, `/projects/[slug]`의 본문과
URL, 기존 콘텐츠/SEO/챗봇 계약은 유지한다. 앞서 언급한 About·Blog 디자인 통일은 이번 계획에 포함하지 않는다.

시각 근거: [사용자 제공 Vante 원문](references/2026-11-05-vante-ribbon-reference.txt).
원문의 단일 HTML, VANTE 상표, 샘플 영상 8개, 가짜 연락/메뉴 버튼은 참고용이며 복제 지시로 취급하지 않는다.
Next.js 앱에 맞게 컴포넌트를 나누고 Hozorica의 실제 프로젝트를 사용한다.

## 화면과 디자인

- 프로젝트를 감상하고 상세를 탐색하는 Experience 화면. 근거 없는 성과나 고객·수치를 추가하지 않는다.
- 사용자 추가 요청에 따라 이 페이지 안에서만 아이보리 `#f5f3ed` 배경, 남색 `#172c52` 본문,
  `#53647b` 보조색, `rgba(23,44,82,.18)` 선을 사용한다. 블루 `#3d6ed5`는 제목과 포커스에 쓴다.
- 기존 SUIT 폰트를 유지한다. 새 Google Fonts 요청은 추가하지 않는다. 데스크톱 바깥 여백 64px,
  1024px 미만 24px. 제목은 `clamp(40px,6.7vw,130px)`, weight 500, 자간 `-.045em`.
- 상단 HOZORICA → `/`, About → `/resume`, Blog → `/blog`, 모든 작업 → `#project-index`.
  빈 MENU/연락 버튼은 만들지 않는다. 상단에 항상 '최호의 프론트엔드 작업'을 읽을 수 있게 둔다.
- 임시 확정 문구 제안: 큰 제목 `IDEAS IN` / `PRACTICE`, 설명
  `프론트엔드와 인터랙션으로 구현한 작업들.`. 최종 문구는 구현 전 계획 검토 때 바꿀 수 있다.
- 첫 화면의 큰 제목은 양 끝에서 시작해 교차한다. 정지/실패 모드에서는 완전한 제목과 목록을 즉시 읽는다.
- 리본이 끝나면 대표 6개가 3×2 그리드로 모인다. 화면비가 `.9` 미만이면 2×3.
  카드에 프로젝트명과 상세 링크를 제공한다. 호버 이름표는 부가 효과이며 유일한 탐색 수단이 아니다.
- 쇼케이스 뒤에는 기존 순서의 전체 프로젝트 11개를 서버 렌더링한 일반 목록으로 제공한다.
  시작부터 '모든 작업'으로 이 목록에 바로 갈 수 있어 연출 관람을 강제하지 않는다.

## 미디어 선정

대표/리본 순서와 자산은 다음 제안으로 고정한다. 기존 `project-data.ts`의 전체 목록 순서는 변경하지 않는다.

| 순서 | slug | 리본 미디어 | 정지 화면 | 최종 그리드 |
|---|---|---|---|---|
| 0 | afterimage | `/projects/afterimage/interaction.mp4` | `/projects/afterimage/card.jpg` | 포함 |
| 1 | still | 정지 이미지 | `/projects/still/card.jpg` | 포함 |
| 2 | kusting | 정지 이미지 | `/projects/kusting/curation.png` | 포함 |
| 3 | comma | `/projects/comma/native-gallery-feed-flow.mp4` | `/projects/comma/native-gallery-feed-flow-poster.jpg` | 포함 |
| 4 | geobugirin | `/projects/geobugirin/posture-feedback.mp4` | `/projects/geobugirin/posture-feedback-poster.jpg` | 포함 |
| 5 | ai-workflow | 정지 이미지 | `/projects/ai-workflow/card-primary-v2.jpg` | 포함 |
| 6 | forensic-agent | 정지 이미지 | `/projects/forensic-agent/card-primary-v2.jpg` | 제외 |
| 7 | nexacro-react-poc | 정지 이미지 | `/projects/nexacro-react-poc/card-primary-v2.jpg` | 제외 |

각 카드는 해당 `/projects/{slug}`로 연결한다. 이미지는 늘이지 않고 cover한다. 서비스 UI가 가로로
잘리는 경우 원본을 포함한 중립 배경 포스터로 별도 내보내되 콘텐츠를 새로 꾸며내지 않는다.
첫 구현은 영상 3개+이미지 5개이며 모든 카드가 동영상인 것처럼 설명하지 않는다.
추가 녹화/영상 생성과 R2/DB 업로드는 별도 작업이다. 외부 샘플 영상을 포트폴리오에 쓰지 않는다.

## 모션 계약

- 일반 문서 스크롤을 사용한다. 기존 홈의 wheel 가로채기/스냅 상태 머신은 재사용하지 않는다.
- 향상 모드에서 track 900svh, stage sticky 100svh. 실제 진행률은 track의 문서 위치를 빼고
  `(scrollY - trackTop) / (trackHeight - stageHeight)`를 0–1로 제한한다.
- 표시 진행률 하나로 제목·리본·그리드를 구동한다. 기준 `.09` 보간은 60Hz 기준이며
  `alpha = 1 - (1 - .09) ** (deltaMs / (1000 / 60))`로 프레임 독립적으로 바꾼다.
- 0–.12 제목이 34svh 올라옴; 0–.58 두 줄이 -50vw/+50vw에서 +76vw/-76vw로 교차함.
  .14–.63 고정 레일 위를 카드들이 통과하고, 각 카드의 레일 이탈 시점부터 .13 진행률 동안
  `1-(1-t)^3`으로 그리드에 착지한다. .52–.57 중앙 설명이 사라지고 .72–.86 구분선이 생긴다.
- 정방향/역방향 모두 같은 진행률로 결정하며 재생 완료 이벤트로 장면을 전진시키지 않는다.
  개별 MP4 프레임은 스크롤 탐색하지 않는다. 공간 배치만 스크롤에 동기화한다.
- 레일의 161 CatmullRom 샘플, arc length 테이블 1201개, 카드 2.1×1.32/gap .03,
  세그먼트 28×3, FOV 35°, 깊이 5.4–24는 원문의 기하 계약을 유지한다.
- 근접 통과에서 카드가 과도하게 접히지 않고, 뒷면에서도 UV를 뒤집어 UI 텍스트가 정상으로 읽혀야 한다.
  색 공간은 실제 소스와 비교해 검증하며 원문의 Linear/NoColorSpace 설정을 맹목적으로 복사하지 않는다.
- .86 이후 대표 6개에 실제 HTML 링크를 화면상 카드와 일치시킨다. 진행 중에는 이 오버레이 링크가
  포커스/클릭을 가로채지 않는다. 전체 목록 링크는 진행률과 무관하게 항상 사용 가능하다.

## 성능·복구·탐색

Three.js는 동적 import로 프로젝트 화면에서만 로드한다. 참조 구현 버전 `three@0.170.0`과
`@types/three@0.170.0`을 사용하되 설치 시 배포/보안/React 호환성을 확인하고 차이가 생기면 기록한다.
CDN import map과 React Three Fiber/GSAP 같은 추가 런타임은 사용하지 않는다.

SSR 기본값은 일반 포스터 목록이다. WebGL 초기화가 성공한 뒤에만 긴 sticky track을 활성화한다.
초기화 실패·context loss·모션 줄이기·saveData에서는 바로 정적 목록으로 복구한다.
영상 오류/자동재생 거절은 그 카드의 포스터로 대체하며 그리드/링크는 계속 동작한다.

영상은 최대 3개 동시 재생, 숨겨진 카드와 hidden 탭에서는 pause. 소스는 필요 시 연결하며
정적 모드에서 MP4를 받지 않는다. DPR 상한 1.5. 미디어/캔버스는 장식으로 취급하고 접근 가능한
제목·프로젝트명·링크는 HTML로 제공한다. 터치에서 hover 없이 탐색한다.
리사이즈에서 같은 진행률을 유지한다. 상세 진입 후 뒤로 가기와 URL hash/앵커 탐색을 지원한다.
컴포넌트 해제 시 RAF, listener, video, VideoTexture, geometry, material, renderer를 정리한다.

## 완료 기준

1664×634와 2558×974의 가로, 1440×900, 390×844, 844×390을 확인한다. 세로 화면에서
헤더·6개 착지 카드·목록 바로가기가 겹치지 않고 가로 overflow가 없어야 한다.
900svh가 모바일에서 과도하게 느껴지면 연출을 줄이는 후속 수정안을 검토하되 첫 구현에서 스크롤을
가로채거나 임의 속도로 이동시키지 않는다. 정적 모드는 긴 연출 없이 바로 모든 작업을 탐색한다.

실제 데스크톱에서 연출 구간 10초 trace의 프레임 간격 p95 33ms 이하를 목표로 기록하고,
초과하면 반복 영상 해상도/DPR을 줄이거나 정적 모드를 적용한다. 이는 아직 측정한 성능 수치가 아니다.
홈/블로그 청크에 Three.js가 추가되지 않는 것과 실제 프로젝트/상세 링크·canonical 보존을 확인한다.

## 출시 방식

먼저 `/experiments/project-ribbon`에 noindex로 구현 → 사용자가 스크롤과 프로젝트 선정을 검토 →
동일 컴포넌트를 `/projects`에 연결 → 운영 후보 검증 → 운영 반영. 실험 단계에는 기존 `/projects`를
유지한다. 기존 목록 컴포넌트를 보관해 빠르게 복구할 수 있게 한다. 이 문서 작성만으로 구현이나
배포를 시작하지 않는다.
