# 익명 댓글과 좋아요

글 하단에서 로그인 없이 랜덤 닉네임으로 댓글을 남기고, 좋아요를 누르거나 취소할 수 있습니다. 댓글은 최신순이며 20개씩 더 불러옵니다. 작성자 수정·삭제 기능은 제공하지 않습니다. 닉네임은 인증된 이름이나 고유 이름이 아니며, 여러 방문자가 같은 닉네임을 사용할 수 있습니다.

## 현재 준비 상태

- 새 D1: `blog-engagement`, APAC, ID `1a801df7-75e9-46d2-998b-4b4d6f5811e2`.
- `db/migrations/0001_engagement.sql`을 실제 D1에 적용했습니다.
- Next.js 서버가 [D1 HTTP API](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)를 호출합니다. Vercel 배포를 유지할 수 있고 DB 자격 증명은 클라이언트에 전달하지 않습니다.
- `.env.local`은 `blog-engagement-production` 운영용 API 토큰으로 연결했습니다. 권한은 지정한 계정의 **D1 Edit**만 포함하며, 토큰 값은 Git에 포함하지 않습니다. 배포 시 호스팅 환경 변수에도 같은 서버 전용 설정을 등록해야 합니다.

## 운영 설정

1. Cloudflare의 API Tokens에서 해당 계정에 한정된 **Account → D1 → Edit** 토큰을 만듭니다. 다른 제품의 권한을 부여하지 않습니다. 계정 내 D1 범위의 권한이며 테이블 단위 권한은 아닙니다.
2. `.env.example`의 `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_D1_DATABASE_ID`, `CLOUDFLARE_D1_API_TOKEN`, `ENGAGEMENT_SECRET`을 로컬 또는 호스팅 환경 변수에 등록합니다. `ENGAGEMENT_SECRET`은 `openssl rand -hex 32` 등으로 생성하고 배포마다 바꾸지 않습니다. 모든 값을 서버 전용으로 유지합니다.
3. Vercel에서는 플랫폼이 덮어쓰는 `x-vercel-forwarded-for` 헤더를 자동으로 사용합니다. 다른 호스팅에서는 신뢰하는 프록시가 반드시 덮어쓰는 헤더만 `ENGAGEMENT_IP_HEADER`로 지정합니다. Vercel 외 환경에서 빈 값은 헤더 기반 제한을 사용하지 않습니다. 이때도 브라우저별 제한은 유지됩니다.
4. 새 데이터베이스로 바꾸는 경우 `wrangler.jsonc`의 계정·DB 식별자와 서버 환경 변수를 함께 바꾸고, `pnpm dlx wrangler@4.159.0 d1 execute blog-engagement --remote --file=db/migrations/0001_engagement.sql --yes`로 스키마를 적용합니다. 이 SQL은 재적용해도 기존 데이터가 삭제되지 않습니다.
5. 배포 후 실제 글에서 댓글 등록·새로고침·좋아요·취소를 확인합니다. 메인 반영 및 운영 환경 설정은 `docs/deployment.md`에 기록합니다.

DB 식별자는 비밀이 아니지만 토큰·서명 비밀키·쿠키·로컬 DB는 Git에 넣지 않습니다. DB 권한·스키마·토큰이 잘못됐을 때 성공한 것처럼 표시하거나 다른 저장소로 대체하지 않고 503과 재시도를 제공합니다.

## 로컬 실행

실제 D1 연결은 환경 변수를 설정한 뒤 `pnpm dev`로 확인합니다. 운영용 토큰 준비 전에도 Node.js 24 이상에서 `.env.local`에 `ENGAGEMENT_STORAGE=sqlite`와 32자 이상의 `ENGAGEMENT_SECRET`을 설정하면 같은 SQL을 사용하는 로컬 미리보기를 쓸 수 있습니다. 이 모드는 `.local/engagement.sqlite`에 저장하고 **production에서는 거부**합니다. SQLite 데이터는 D1으로 자동 복사하지 않습니다.

검증: `pnpm test:engagement`, `pnpm test:article`, `pnpm test:posts`, `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build`.

## 익명성·중복·스팸 제한

- 서버가 발급하고 서명한 무작위 브라우저 ID를 HttpOnly·SameSite=Lax 쿠키에 1년 보관합니다. HTTPS에서는 Secure를 적용합니다. DB에는 그 ID의 HMAC만 저장하고 공개 API에서는 반환하지 않습니다.
- 좋아요는 `(글, 브라우저)` 조합으로 하나이며 취소할 수 있습니다. 요청은 반전 명령이 아니라 원하는 상태를 보내므로 중복 요청으로 수가 늘지 않습니다.
- 쿠키를 지우거나 다른 기기·브라우저를 사용한 사람을 동일인으로 식별할 수 없습니다. 이 기능은 사람당 한 번이라는 보장을 하지 않습니다.
- 댓글은 1~1,000자 평문, 제공된 랜덤 닉네임만 허용합니다. HTML을 렌더링하지 않고 SQL 매개변수를 사용합니다. 본문은 최대 8KiB까지만 읽습니다.
- 브라우저당 댓글은 30초 간격입니다. 별도로 브라우저당 1분에 댓글 요청 5회·좋아요 요청 60회, 신뢰 가능한 네트워크 헤더가 있으면 네트워크당 댓글 요청 10회·좋아요 요청 120회로 제한합니다. 같은 네트워크를 쓰는 방문자는 한도를 공유합니다.
- 네트워크 식별자는 비밀키로 HMAC 처리하고 원본 IP는 저장하거나 로그에 남기지 않습니다. 제한 기록은 새 쓰기 요청 시 하루보다 오래된 항목을 제거합니다. 분산 봇 공격을 완전히 막는 기능은 아니므로 필요하면 호스팅의 요청 제한이나 Turnstile을 별도 적용합니다.
- 쓰기는 같은 Origin의 JSON과 유효한 서명 쿠키를 요구합니다. 댓글 ID는 요청 재시도에도 유지해 네트워크 오류 후 같은 댓글이 중복 저장되지 않게 합니다.

## 운영자 댓글 관리

공개 API에는 수정·삭제·관리자 기능이 없습니다. 운영자는 Cloudflare D1 콘솔에서 필요한 댓글을 찾은 뒤 숨길 수 있습니다. 숨긴 댓글은 공개 목록·집계에서 제외됩니다.

```sql
SELECT id, slug, nickname, body, created_at
FROM comments WHERE hidden = 0 ORDER BY created_at DESC LIMIT 100;

-- 실제 확인한 댓글 ID를 바인딩하거나 따옴표 안에 넣습니다.
UPDATE comments SET hidden = 1 WHERE id = '확인한-댓글-ID';
```

영구 삭제는 D1 콘솔에서 해당 ID만 확인해 실행합니다. 게시물 slug를 바꾸면 기존 댓글·좋아요도 해당 slug로 옮겨야 연결이 유지됩니다.

## 디자인

[토스 댓글 폼](https://toss.tech/article/taste)의 랜덤 닉네임·변경 버튼·넓은 입력창·작성 후 수정/삭제 불가 흐름을 참고했습니다. 원본 캐릭터 이미지는 복제하지 않았습니다. 블로그의 SUIT Bold, 15px 본문, 기존 읽기 폭과 여백은 유지하고 댓글·좋아요만 글 바깥 공통 하단에 추가합니다. 새 영역은 기존 무채색과 라이트/다크 토큰을 따릅니다.

## 낙관적 업데이트

좋아요는 클릭 즉시 상태·개수를 반영하고 서버 응답과 맞춥니다. 실패하면 이전 좋아요 상태로 되돌리되 동시에 추가된 댓글 등 다른 변경은 보존합니다.

댓글은 클릭 즉시 목록·개수에 추가하고 입력창을 비웁니다. 정상 처리 중에는 로딩 문구 없이 바로 표시하고, 성공하면 같은 ID의 서버 댓글로 교체합니다. 실패하면 임시 댓글을 제거하고 글자 수·개수를 복구하며 원래 입력의 공백·줄바꿈까지 되돌립니다. 재시도는 같은 댓글 ID를 사용하므로 응답 유실 후에도 중복 저장하지 않습니다. 저장 중에는 중복 실행을 막습니다.

## 닉네임과 동물 프사

랜덤 닉네임의 동물을 8종 프사에 연결합니다. 처음 배정된 닉네임부터 브라우저 저장소에 기록해 새로고침에도 유지하며, 랜덤 변경 시 닉네임과 동물이 함께 바뀝니다. 이미 작성한 댓글은 D1의 저장된 닉네임에서 프사를 결정하므로 이후 랜덤 변경에 영향을 받지 않습니다. DB 필드 추가나 기존 댓글 수정은 필요하지 않습니다. 동물 SVG는 직접 작성한 로컬 아이콘으로 외부 이미지 서비스에 방문자 정보나 닉네임을 보내지 않습니다.
