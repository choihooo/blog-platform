# 홈·포트폴리오 미사용 파일 정리

현재 `/`의 스크롤 홈과 `/projects`의 바탕화면을 기준으로 실제 라우트·import·에셋 참조를 확인했다.
Graphify로 projects, scroll-story, navigation의 49개 파일을 분석한 결과는 207개 노드, 436개 연결,
9개 그룹이다. 그래프는 정리 전 상태이며, CSS와 동적 미디어 경로는 별도로 확인했다. 연결 수만으로
삭제 여부를 결정하지 않았다.

- 런타임 호출부가 없는 이전 `ProjectsPage`와 피드 전용 CSS를 제거했다. 현재 로딩 스켈레톤이 쓰는
  기본 폭과 로딩 스타일은 유지했다. 옛 파일을 읽던 통합 테스트는 현재 바탕화면 라우트를 확인한다.
- 스토리 데이터에서 읽는 곳이 없는 image, video, description, backdrop 필드와 렌더링되지 않는
  backdrop CSS를 제거했다.
- 이전 `plates/`, `plates-centered/`, 알파 WebM, 인사·필기 PNG 등 56개 미디어를 제거했다. 총
  18,490,967바이트(약 17.6MiB)이며 이전 파일은 Git 이력에서 복원할 수 있다.
- 현재 `plates-ultrawide-v2/`의 wide/tall/short 반복·전환·정지 화면 36개와 생성 정보를 유지했다.
  바탕화면이 사용하는 `working.png`, 프로젝트 미디어와 픽셀룸 보관 에셋도 유지했다.
- 로컬에만 남아 있던 `app/@modal/.DS_Store`와 빈 디렉터리를 제거했다. 소스가 없는 디렉터리도
  Next.js가 parallel route로 인식해 default 파일 누락 오류를 만들었다. Git 변경에는 포함되지 않는다.
- 기존 실험 URL의 영구 리다이렉트와 noindex 픽셀룸 보관 페이지는 유지했다. CMS·DB·R2 데이터,
  비밀키·로컬 모델·기존 stash는 수정하지 않았다.

분석 산출물은 원래 작업 폴더의 `outputs/cleanup-graphify/`에 보관한다. `graph.html`, `graph.json`,
`GRAPH_REPORT.md`, `obsidian/`, 삭제한 미디어 전체 목록 `removed-media.json`을 포함한다. 문서 의미
추출 토큰은 입력 약 7,000/출력 약 2,000으로 추정하며 실제 사용량을 측정한 값은 아니다.

## 검증 결과

- Blog 테스트 412개/45파일, lint, typecheck, format 검사와 production build 통과.
- 현재 3개 화면 비율의 반복·전환·정지 화면 36개와 바탕화면 이미지의 실제 파일 존재를 확인했다.
- 로컬 `.DS_Store` 잔여 라우트를 제거한 뒤 빌드를 재실행했다. 콘텐츠 API 연결이 한 번
  `ECONNRESET`으로 끊겼으나 공개 API HTTP 200 확인 후 재실행한 빌드는 통과했다.
- 배포와 원격 데이터 변경은 수행하지 않았다.

## 추가 조사: 블로그·챗봇·CMS·공유 패키지

Graphify 분석 범위를 나눠 공개 앱/RAG 137개, CMS 170개, 공유 패키지/RAG Worker 69개 등 총 376개
파일을 조사했다. 정리 전 연결 그래프는 1,824개 노드·4,661개 연결·91개 그룹이다. 산출물은 원래 작업
폴더의 `outputs/cleanup-graphify-other/`에 보관하며 HTML·JSON·Obsidian 그래프와 `GRAPH_REPORT.md`,
TypeScript import 분석 `import-audit.json`을 포함한다.

- 라우트에서 호출되지 않는 `BlogArchiveList`와 아카이브 전용 CSS·로딩 애니메이션을 제거했다.
- `PostPage`의 archive 표시 옵션은 넘겨주는 호출부가 없어 제거했다. 일반 페이지의 클래스와
  본문·분류·작성자·목차·커버·추천글·공유·JSON-LD·OG 썸네일을 유지한다.
- 모달 내 이동에서만 필요했던 replaceLinks 전달을 본문·추천글·목록·태그 페이지·breadcrumb에서
  제거했다. 기존 정식 페이지 호출부는 모두 기본값 false를 사용하므로 history 동작은 같다.
- 정리 전후에 같은 본문 렌더링·커버 1회 노출·OG·canonical·빈 목차·404 동작을 확인하는 4개 회귀
  테스트가 통과했다.
- import 분석의 나머지 후보는 방문자 질문 corpus와 analytics/SEO 테스트 fixture였다. 실제 테스트가
  사용하므로 유지했다. PostCSS 설정은 프레임워크 진입점이다. CMS의 저장소 어댑터·인증·preview
  token·발행 retry·migration과 공유 패키지의 공개 API도 유지했다. CMS 런타임과 공유 패키지는
  수정하지 않았다.

추가 분석의 문서·이미지 의미 추출 토큰은 입력 약 3,850/출력 약 5,900으로 추정한다. 벤치마크는 약
111,972토큰의 원문 대비 평균 1,625토큰의 그래프 질의를 계산한 추정치이며 실제 모델 사용량이나 질의
정확도를 측정한 결과가 아니다.

추가 정리 후 Blog 테스트 416개/46파일, lint, typecheck, format 검사와 production build가 모두
통과했다. 변경은 로컬 정리 브랜치에 커밋하며 이 단계에서도 배포·DB/R2 쓰기는 수행하지 않았다.

배포 전 독립 검토에서 로딩 스켈레톤이 사용하는 모바일 `.work-feed` 여백 규칙을 확인해 복원했다. 이전
피드의 프로필·타일 스타일과 현재 로딩 화면의 스타일을 구분해 유지한다.
