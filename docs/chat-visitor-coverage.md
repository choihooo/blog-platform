# 방문자 질문 대응 확장 · 2026-09-07

## 2차 확장 결과

- 앞서 제안한 질문 139개를 `visitor-questions.ts`에 고정했다. 전 항목의 API 응답/분기 계약 테스트와
  별도 동작 테스트를 포함해 Blog 339개 테스트가 통과했다.
- 비교표(프로젝트의 실제 역할·기술·성과, 글은 다시 확인한 발췌 비교), 1~3개 선택, 짧은 발췌 요약,
  다음 프로젝트/글 목록을 추가했다.
- 최근 5개 검색 스냅샷을 메모리에 유지해 “아까 말한 첫 번째”를 복원한다. 각 스냅샷은 검색어와 최대
  3개 제목만 보관하며, 중첩/과도한 히스토리를 서버에서 거부한다.
- 인사/안내처럼 출처 없는 응답 때문에 기존 검색 맥락이 사라지지 않도록 했다.
- `대표 프로젝트 → 비교표 → 두 개 → 2번 역할 → 성과 → 이전 첫 번째 → 다른 목록` 로컬 API 흐름 확인.
  최초 확인에서 이전 프로젝트 복원이 원격 검색에 의존해 실패한 것을 수정하고, 재검증 HTTP 200 및
  회귀 테스트를 추가했다.
- lint·타입 검사·build 통과. 마지막 복원 보완 후 테스트 및 lint 재통과.

### 검증의 의미와 한계

139개 테스트 중 원격 검색은 테스트 응답으로 대체한다. 따라서 전체 질문의 **처리 경로**를 검증한
것이지, 운영 자료의 충분성이나 Kanana의 답변 정확도를 100% 보장하는 것은 아니다. 자유로운 기술
질문은 실제 검색/모델 경로를 사용한다. 답변에 필요한 원문이 없으면 확인 불가로 안내하거나 범위를
되묻는다.

기억은 최근 5개 스냅샷 범위이며 새로고침 후 복원하지 않는다. 과거 목록이 여러 개면 가장 최근 다중
목록을 선택한다. 전체 아카이브는 100개 조회 범위, 글의 난이도 평가는 미등록이다. “쉽게”는 현재 짧은
근거 발췌를 제공하며 전문 용어를 재작성하는 품질은 보장하지 않는다. 이력서에 없는 현재 채용
의사·연봉·개인 정보는 생성하지 않는다.

아래는 1차 구현 당시 기록이다. 비교표·이전 목록·다음 목록의 미구현 표기는 위 2차 결과로 대체한다.
운영 배포/커밋은 별도 요청 전까지 하지 않는다.

## 구현

- `visitor.ts`: 인사·탐색 안내·소개·연락 경로·서비스 설명·현재 의사 미확인·비공개 정보 처리. 서비스
  설명은 현재 구현에서 확인한 사실만 사용한다.
- 공개 프로젝트의 정확한 제목/slug를 확인한 뒤 역할, 팀 구성, 기술, 성과, 외부 링크, 관련 글을
  데이터에서 제공한다. 클라이언트가 전달한 제목 자체는 근거로 사용하지 않는다.
- `follow-up.ts`: 짧은 역할·성과·링크 질문의 대상 유지. 모호한 다중 결과는 순서를 되묻는다. 회사
  제외와 1인 개발을 구분하고, 최근 요청은 AI/React 주제를 유지한다.
- 최신 글과 AI 제외 조건은 공개 글의 발행일·제목·태그로 처리한다. 최대 100개 공개 글 범위이며, 이
  범위를 넘는 전체 아카이브 탐색은 추후 페이지 순회가 필요하다.
- 공개 글 조회 실패를 빈 결과로 숨기지 않는 strict 조회 경로 추가. 기존 블로그 목록 동작은 유지한다.
- 기술별 경험 질문을 일반 경력 소개로 덮어쓰던 규칙을 좁혔다. 구체적인 기술 판단·설계 질문은 기존
  근거 검색 경로로 전달한다.
- 채팅 본문의 Markdown 링크를 안전한 HTTPs/상대경로 링크로 렌더링한다. HTML이나 실행 가능한 URL은
  해석하지 않는다.

## 검증 범위

- Blog 193개 테스트 통과(기존 134개 + 신규 59개). 질문 분류, 실제 프로젝트 필터, 공개 글 정렬·초안
  제외, 후속 대화 API, 링크 안전성 포함.
- 회사 프로젝트 → 두 번째 역할 → 성과 → 원문 링크 연속 요청 검증.
- 자동 테스트는 브라우저 모델의 모든 자연어 답변 정확성을 보증하지 않는다.

## 남은 범위

- 앞서 나열한 모든 표현을 전용 규칙으로 처리한 것은 아니다. 자유로운 기술 질문·요약은 기존 검색과
  모델에 의존한다.
- 전체 대화 이력이 아닌 직전 검색어와 최대 3개 제목을 유지한다. 오래전 목록 복원, 비교표, 페이지
  넘김, 요청 개수의 일반화는 미구현이다.
- 글의 난이도, 가장 뛰어난 작업, 실패 경험, 기술 선택의 대안은 별도 자료 또는 근거 검증이 필요하다.
  임의로 등급이나 경험을 생성하지 않는다.
- 최신 글 기능은 기존 D1 API 환경 설정이 필요하다. Worker 검색만 설정된 로컬에서는 조회 실패를 정상
  오류로 보여준다.
- 이번 변경은 로컬에만 적용했다. 별도 커밋·푸시·운영 배포는 하지 않았다.
