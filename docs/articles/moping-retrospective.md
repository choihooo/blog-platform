## 지도 API와 모바일 화면

모핑은 모임 구성원이 가고 싶은 장소를 공유 지도에 모아, 함께 방문할 공간을 고르는 서비스입니다. 각자가 등록한 장소의 위치를 지도에서 확인하고, 후보 장소의 정보를 살펴볼 수 있습니다.

이전까지는 데스크톱 화면 위주로 개발했습니다. 모핑은 처음부터 모바일을 우선으로 만드는 서비스였고, 저는 지도 API를 활용하고 모바일을 기준으로 반응형 화면을 구현해보고 싶어 참여했습니다.

프론트엔드에서는 Naver Map 기반 지도와 마커, 현재 위치를 연결하는 작업을 맡았습니다. 이후 장소 목록과 선택한 장소의 정보를 바텀시트에 표시하고, 드래그와 핀 선택 동작을 구현했습니다.

## 핀을 하나씩 눌러야 했던 화면

기존 바텀시트에는 모임명과 참여자 프로필이 표시됐습니다. 참여자를 선택하면 그 사람이 등록한 장소가 지도에 나타났습니다. 장소 정보를 보려면 핀을 누른 뒤 툴팁의 ‘가게 정보 바로 보기’ 링크로 이동해야 했습니다.

장소마다 핀을 하나씩 눌러야 해서 불편했습니다. 팀에서 등록된 장소를 목록으로 한 번에 볼 수 있게 하자는 의견이 나왔고, 바텀시트에 장소 목록을 추가했습니다.

각 항목에는 장소명·분류·아이콘과 상세정보 버튼을 넣었습니다. 장소 항목과 버튼은 개별 컴포넌트로 분리했고, 일반 장소와 추천 장소도 상태에 따라 나눠 보여주도록 했습니다.

후속 작업에서는 지도 위 툴팁에 표시하던 장소 정보도 바텀시트로 옮겼습니다. 핀을 선택하면 목록 대신 장소명·분류·북마크한 사람과 상세 링크가 나타나고, 지도 빈 곳을 누르면 다시 목록으로 돌아오도록 연결했습니다.

이제 핀 선택은 지도 위 표시와 바텀시트의 내용을 함께 바꾸는 동작이 됐습니다.

## 핀 하나를 누르면, 이전 핀은 원래대로

### 새 핀보다 먼저 처리할 이전 핀

커스텀 핀에서 어려웠던 부분은 선택과 해제 이벤트를 연결하는 일이었습니다. 누른 핀을 키우는 것만으로는 끝나지 않았습니다. 다른 핀을 누르면 이전 핀은 원래대로 돌아가야 했고, 지도 빈 곳을 누르면 선택 표시가 없어져야 했습니다.

예를 들어 A 핀을 누른 다음 B 핀을 누르면, B의 크기를 바꾸기 전에 A를 기본 크기로 돌려야 했습니다. 지도 빈 곳을 누를 때도 마지막으로 선택한 핀을 찾아 되돌려야 했습니다. 두 동작 모두 이전에 어떤 핀을 선택했는지 알아야 처리할 수 있었습니다.

이를 위해 이전에 선택한 핀을 <code>ref</code>에 저장해뒀습니다. 다른 핀을 누르면 저장해둔 핀을 기본 크기로 돌리고, 새 핀을 키운 뒤 다음 선택에서 되돌릴 대상으로 저장했습니다. 지도 빈 곳을 누르면 저장된 핀을 원래 크기로 되돌리고 선택 상태를 비웠습니다. 정보창도 함께 닫도록 했습니다.

이렇게 선택 처리를 새로 누른 핀의 변화와 이전 핀의 복원으로 나눠 연결했습니다.

### 바텀시트의 정보와 지도 객체

선택한 장소의 정보는 공통 상태로 관리해 바텀시트와 연결했습니다. 반면 이전 선택 핀과 정보창은 참조로 관리했습니다. 바텀시트에는 어떤 장소를 보여줄지가 필요했고, 지도에서는 어떤 객체의 표시를 되돌릴지가 필요했습니다.

이 구현에서 <code>ref</code>는 이전 지도 객체를 다시 찾아 조작하는 역할을 했습니다. 장소 정보는 화면에 표시할 상태로, 핀과 정보창은 지도 API로 조작할 객체로 나눠 다뤘습니다. 마커를 생성하는 처리는 마커 데이터가 바뀔 때 실행하도록 변경했습니다.

핀 아래에는 장소명을 표시하기 위해 HTML 기반 마커를 사용했습니다. 기본 핀은 28×32px, 선택한 핀은 35×40px로 표시하고, 크기에 맞춰 이미지의 기준점과 장소명 위치도 조정했습니다. [핀 선택과 표시를 수정한 기록](https://github.com/Team-pingping/pingping-FE/commit/b06a3af443b880015ff15fb5fe648fd29550ef40)에 이 변경이 남아 있습니다.

## 화면 높이가 달라도 비슷한 비율로

바텀시트에는 목록을 담는 것과 함께 펼쳐지는 동작도 필요했습니다. 기존에는 드래그 위치가 기준값을 넘었는지에 따라 열리거나 닫혔습니다. 초기에는 위·중간·아래 세 정지 위치를 두고, 드래그를 놓으면 가장 가까운 위치로 이동하도록 바꿨습니다. 드래그 중에는 이동 범위를 제한했습니다.

처음 지정한 정지 위치는 고정 픽셀값이었습니다. 하지만 모바일 화면 높이에 따라 바텀시트가 보이는 정도가 달라졌습니다. 화면 크기가 달라도 비슷한 비율로 펼쳐지게 하고 싶었습니다.

그래서 화면 높이를 세 구간으로 나누고, 각 구간의 비율과 실제 높이로 이동 좌표를 계산하도록 바꿨습니다. 창 크기가 바뀌면 기준점도 다시 계산했습니다. 이 과정은 [화면 높이 대응 작업](https://github.com/Team-pingping/pingping-FE/commit/992d3cd98f179f40a9bcf2c680bbcd7a45783867)에 정리돼 있습니다.

## 구현 후 확인한 범위

구현 후에는 직접 화면을 조작하며 동작을 확인하고 QA 검수를 받았습니다. 목록에서 장소를 살펴보고, 지도에서 선택한 장소를 같은 바텀시트에서 확인할 수 있게 됐습니다.

다만 탐색 시간이나 사용자 만족도를 따로 측정하지는 않았습니다. 새로운 탐색 경로를 제공했지만, 실제 사용에 얼마나 도움이 됐는지는 수치로 확인하지 못했습니다.

## 코드를 다시 보며 나온 개선안

경험을 정리하면서 AI 도구로 당시 코드를 검토했습니다. 아래는 그 과정에서 나온 제안으로, 당시의 판단이나 이미 적용한 개선과는 구분됩니다.

핀 선택과 관련해서는 장소를 식별하는 기준을 바꿀 여지가 있었습니다. 검토한 코드에서는 장소명으로 선택한 장소를 찾고 있어, 이름이 같은 장소가 여러 개라면 다른 항목을 선택할 가능성이 있습니다. 고유 ID로 선택 상태를 관리하고, 이름은 같지만 위치가 다른 두 장소를 번갈아 눌러 지도와 바텀시트의 정보가 일치하는지 확인하는 방식이 개선안입니다.

화면 크기가 바뀌면 기준점은 다시 계산했지만, 이미 펼쳐진 시트를 새 기준점에 맞춰 옮기는 처리는 확인되지 않았습니다. 현재 시트 위치도 함께 조정하고, 고정된 목록 높이를 남은 공간에 맞추는 방식이 개선안입니다. 시트 전체의 드래그와 내부 목록 스크롤이 터치 환경에서 충돌하는지도 점검할 항목입니다. 실제 충돌이나 개선 효과를 실행해 확인한 것은 아닙니다.

## 화면에 보여줄 정보와 되돌릴 객체

이번 구현을 돌아보면, 핀 선택의 핵심은 새로 누른 장소만 표시하는 데 있지 않았습니다. 이전 핀을 되돌리고 선택을 해제하는 동작까지 연결해야 했습니다. 바텀시트에 보여줄 장소 정보는 상태로 관리하고, 이전 핀을 되돌리는 데 필요한 지도 객체는 참조로 관리했습니다.

모핑에서는 해보고 싶었던 지도 API 활용과 모바일을 기준으로 한 반응형 화면 개발을 경험했습니다. 커스텀 핀의 선택과 해제, 화면 높이에 따른 바텀시트 위치를 조정하면서 원하던 동작을 직접 구현할 수 있어서 좋았습니다.
