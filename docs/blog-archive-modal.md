# 픽셀룸 블로그 아카이브 모달 · 2026-09-07

## 구현 내용

- 픽셀룸의 기존 Blog 핫스팟은 `/blog` 링크를 유지한다.
- Next.js App Router의 `@modal/(.)blog` 인터셉트 라우트가 클라이언트 이동에서 픽셀룸 위에 아카이브
  창을 표시한다. 글 상세, 검색, 페이지네이션, 카테고리, 태그도 같은 방식으로 확장했다.
- 픽셀룸에서 클라이언트 링크로 이동하면 `@modal` 인터셉트 라우트가 픽셀룸 위에 창을 띄운다. 반면
  직접 URL을 열거나 새로고침하거나 검색엔진이 접근하면 원래 full-page 문서를 렌더링한다. 따라서
  동일한 콘텐츠를 모달 UX와 canonical SEO 페이지 양쪽에서 사용할 수 있다.
- 창은 레퍼런스의 데스크톱 운영체제 창을 참고해 제목 표시줄, 닫기 버튼, 카테고리 트리, 글 목록,
  썸네일, 날짜, 읽기 시간, 태그, 오른쪽 화살표를 제공한다.
- 글 항목을 누르면 `@modal/(.)blog/[slug]`로 이어지고, 기존 상세 글 렌더러를 같은 창 안에 표시한다.
- 검색·카테고리·태그·페이지네이션 링크도 `@modal` 하위 라우트로 연결되어 창과 픽셀룸 배경을
  유지한다.
- 닫기 버튼·ESC·배경 클릭은 블로그 창을 닫아 픽셀룸으로 돌아가고, 상세 상단의 목록 버튼은 아카이브
  목록으로 돌아간다.
- 모달 parallel route에 로딩 fallback을 추가해 글 상세를 불러오는 동안에도 창 안에서 상태를
  보여준다.
- 640px 미만에서는 창을 전체 화면으로 바꾸고 카테고리는 가로 스크롤 목록으로 축소한다.
- `prefers-reduced-motion`에서는 창 등장 애니메이션을 최소화한다.

## 데이터와 환경

아카이브는 새 데이터 모델을 만들지 않고 `getPublishedPosts`, `listCategories`의 기존 D1/R2 콘텐츠를
사용한다. 로컬에는 D1 토큰을 복사하지 않기 위해 `BLOG_CONTENT_PROXY_URL`을 통해 CMS Vercel 서버의
읽기 전용 `/api/public-content`를 호출하도록 구성했다. D1 토큰은 CMS 서버에서만 사용되고, 브라우저나
로컬 `.env.local`로 노출되지 않는다. 이 API는 발행된 글과 카테고리만 반환하며, 글 상세 요청도 같은
프록시를 통해 처리한다.

## 사용하지 않게 된 코드 기록

- 기존 블로그·프로젝트·이력서 페이지 엔트리는 직접 URL과 SEO용 canonical 콘텐츠를 제공하고, 픽셀룸
  클라이언트 이동에서는 같은 콘텐츠를 인터셉트 모달로 표시한다. 내부 렌더러와 `PostListView`는 모달
  콘텐츠에서 재사용한다.
- 챗봇의 내부 참고 자료 링크는 새 탭 대신 Next 내부 링크로 바꿔 같은 인터셉트 모달을 사용한다.
- 블로그 아카이브 전용 컴포넌트와 스타일만 새로 추가했다. 새 컴포넌트 중 현재 사용하지 않는 파일은
  없다.
- 셸 이스케이프로 잘못 생성된 임시 라우트 디렉터리 이름은 정상적인 `(.)blog/[slug]` 경로로 정리했다.
- 초기 블로그 앱에 만들었던 `/api/content` 초안은 CMS 프록시로 구조를 확정하면서 삭제했다. 현재
  사용하지 않는 프록시 라우트 파일은 없다.

## 검증

- Blog 테스트 345개 통과.
- 아카이브 라우트·픽셀룸 링크·상세 전환·반응형 스타일 계약 테스트 추가.
- `pnpm --filter @blog-platform/blog lint`, 타입 검사, `build` 통과.
- CMS Production의 `/api/public-content`가 공개 글 33개와 카테고리 12개를 반환하는 것을 확인했다.
- 로컬 픽셀룸에서 `BLOG ARCHIVE` 창에 33개 글과 카테고리가 표시되고, 첫 글 상세가 같은 모달 안에서
  렌더링되는 것을 브라우저로 확인했다.
- `pnpm --filter @blog-platform/cms exec tsc --noEmit`, CMS lint/build도 통과했다.
