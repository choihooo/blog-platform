모핑에 참여하기 전에는 데스크톱 화면 위주로 개발했습니다. 지도 API를 활용해보고 싶었고, 모바일을 기준으로 반응형 화면도 만들어보고 싶었습니다. 모바일을 우선으로 만드는 모핑에서 두 가지를 함께 해볼 수 있었습니다.

모핑은 모임 구성원이 가고 싶은 장소를 공유 지도에 모아, 함께 갈 곳을 고르는 서비스입니다. 지도에서 각 장소의 위치와 누가 저장했는지를 확인할 수 있습니다.

저는 Naver Map을 연결하고, 장소 핀과 현재 위치를 표시하는 작업을 맡았습니다. 지도 아래의 바텀시트에 장소 목록을 넣고, 핀을 누르면 해당 장소의 정보를 보여주는 작업도 했습니다.

## 길거리에서 만난 사람들

기획 과정에서는 오프라인 인터뷰에도 참여했습니다. 핫플레이스 길거리로 나가 인터뷰할 사람들을 직접 모집했습니다.

인터뷰에 응해준 사람 중에는 외국인도 있었습니다. 말이 잘 나오지 않아 버벅거리면서 파파고를 써가며 대화했습니다.

## 핀을 하나씩 누르는 게 불편해서

처음 바텀시트에는 모임 이름과 참여자 프로필이 있었습니다. 참여자를 누르면 그 사람이 등록한 장소가 지도에 나타났지만, 등록된 장소를 목록으로 볼 수는 없었습니다.

장소 정보를 보려면 핀을 누르고, 툴팁에 나타난 ‘가게 정보 바로 보기’ 링크를 열어야 했습니다. 다른 장소가 궁금하면 다시 해당 핀을 찾아 눌러야 했고요. 후보 장소를 한 번에 살펴보고 싶을 때 이 방식이 불편했습니다.

팀에서도 장소를 목록으로 볼 수 있으면 좋겠다는 의견이 나왔습니다. 바텀시트를 펼치면 장소 이름과 분류가 목록으로 나오고, 각 항목의 상세정보 버튼으로 해당 장소의 링크를 열 수 있게 했습니다. 이제 지도에서 핀을 찾지 않아도 목록을 훑어보며 장소를 확인할 수 있었습니다.

지도 위 툴팁에 있던 장소 정보도 바텀시트로 옮겼습니다. 핀을 누르면 목록 대신 선택한 장소의 이름과 분류, 저장한 사람들과 상세 링크가 나타났습니다. 지도 빈 곳을 눌러 선택을 해제하면 다시 목록으로 돌아오도록 했습니다.

## 생각대로 움직이지 않던 핀

커스텀 핀에서는 선택과 해제 이벤트를 연결하는 일이 어려웠습니다. 누른 핀을 크게 표시하고, 다른 핀을 누르면 이전 핀은 원래 크기로 돌아가야 했습니다. 지도 빈 곳을 눌렀을 때는 선택 표시가 없어져야 했고요.

A 핀을 선택한 뒤 B 핀을 누르는 상황이라면, A를 되돌리고 B를 키워야 합니다. 빈 지도를 눌렀을 때도 마지막으로 선택한 핀을 찾아 되돌려야 하니, 이전에 어떤 핀을 선택했는지 저장해둘 필요가 있었습니다.

이전에 선택한 핀을 `ref`에 저장해 처리했습니다. 다른 핀을 누르면 저장된 핀을 기본 크기로 돌리고 새 핀을 키운 뒤, 다음에 되돌릴 대상으로 저장했습니다. 빈 지도를 누르면 마지막 핀을 원래 크기로 돌리고 선택 상태를 비웠습니다.

바텀시트에 표시할 장소 정보는 상태로 관리했습니다. 핀 선택이 바뀌면 새 장소의 정보를 보여주고, 선택을 해제하면 목록을 보여주도록 연결했습니다. 지도에서는 핀의 크기를 바꾸고, 시트에서는 그에 맞는 내용을 보여주는 식으로 동작을 맞췄습니다.

핀 아래에는 HTML 기반 마커로 장소 이름을 붙였습니다. 선택한 핀이 커져도 지도 좌표에 맞게 보이도록 이미지의 기준점과 글자 위치도 조정했습니다.

모핑 화면과 에셋을 바탕으로 만든 데모입니다. 지도와 장소·참여자 데이터는 예시입니다. 핀을 누르거나 바텀시트를 드래그해볼 수 있습니다.

## 모바일 화면마다 달랐던 바텀시트

바텀시트를 움직이는 방식도 바꿨습니다. 기존에는 드래그한 위치가 기준을 넘었는지에 따라 열리거나 닫혔습니다. 중간에도 멈출 수 있도록 정지 위치를 추가하고, 손을 놓으면 가장 가까운 위치로 이동하게 했습니다. 드래그 중에는 정해진 범위를 벗어나지 않도록 제한했습니다.

처음에는 정지 위치를 픽셀값으로 지정했습니다. 하지만 모바일 화면 높이에 따라 시트가 보이는 정도가 달라졌습니다. 같은 거리만큼 움직여도 화면에서 차지하는 비율은 달랐습니다.

화면 크기가 달라도 비슷한 비율로 펼쳐지게 하고 싶었습니다. 그래서 화면 높이를 구간별로 나누고, 구간에 맞는 비율과 실제 높이로 정지 위치를 계산하도록 바꿨습니다. 창 크기가 바뀌면 기준점도 다시 계산했습니다.

접었을 때는 모임과 참여자 정보를, 펼쳤을 때는 장소 목록을 볼 수 있게 했습니다. 시트가 어디에 멈출지 조정하면서 그 안의 내용이 어떻게 보이는지도 함께 맞춰갔습니다.

## 개발자들끼리 일본으로

함께하던 개발자들과 일본으로 해커톤을 다녀오기도 했습니다. 부산 해양 데이터 해커톤 공고를 봤는데, 배로 일본을 오가는 동안 해커톤을 하고 일본에서는 네 시간 정도 자유시간을 준다고 했습니다. 기획자와 디자이너들 몰래 개발자들끼리 참가했습니다.

그런데 배멀미가 심해서 코딩을 하다가 토하기도 했습니다.

일본에 도착해서 저는 동생과 먹을 것을 찾아다녔습니다. 먹고 싶은 것을 사 먹고 포장하는 동안, 형과 누나는 옷을 사러 다녔습니다.

부산에 돌아와서도 같이 놀기로 했는데, 숙소에 들어가자 다들 뻗어서 잠들어버렸습니다. 결국 부산에서는 같이 놀지도 못했습니다.

## 모핑을 만들고 나서

구현한 화면은 직접 조작해보고 QA 검수도 받았습니다. 목록을 추가하면서 장소를 살펴보는 방법은 늘었지만, 탐색 시간이나 사용자 만족도가 얼마나 달라졌는지는 따로 측정하지 않았습니다.

모핑에서는 해보고 싶었던 지도 API 활용과 모바일 화면 개발을 경험했습니다. 어려웠던 핀의 선택과 해제를 연결하고, 바텀시트도 원하는 대로 움직이게 구현해서 좋았습니다. 처음에 해보고 싶다고 생각했던 것들을 직접 조작할 수 있는 화면으로 완성했습니다.
